# ADC 测量问题与排查记录

本文记录当前相电压、BEMF、母线电压和电流采样相关问题。记录中的“已确认”表示已经通过代码、原理图或实测得到；“待确认”表示不能直接作为正式参数使用。

## 1. 当前测量链路

| 项目 | MCU 输入 | 当前状态 |
|---|---|---|
| U 相 BEMF / 相电压 | PF6 / ADC3_IN4 | 已接入 ADC3 注入采样和 VOFA+ |
| V 相 BEMF / 相电压 | PF7 / ADC3_IN5 | 已接入 ADC3 注入采样和 VOFA+ |
| W 相 BEMF / 相电压 | PF8 / ADC3_IN6 | 已接入 ADC3 注入采样和 VOFA+ |
| 母线电压 | PF9 / ADC3_IN7 | 已接入 ADC3 注入采样和 VOFA+ |
| U/V/W 三相电流 | PA3/PA4/PA6 / ADC1 | ADC 已配置，软件尚未完成电流换算 |

ADC3 四个 Rank 使用 TIM1 CC4 触发，采样结果由 ADC3 注入回调保存，应用层完成电压换算。

## 2. 原理图换算关系

配套原理图给出的关系为：

```text
Motor_EMFU = Motor_U / 37
Motor_EMFV = Motor_V / 37
Motor_EMFW = Motor_W / 37
Motor_VBUS_ADC = POWER / 37 + 1.24 V
Motor_EMF*_ADC = Motor_EMF* + 1.24 V
```

因此软件换算模型为：

```text
ADC电压 = ADC原始值 × ADC_VREF / 4095
实际相电压或 BEMF = (ADC电压 - BEMF_OFFSET_V) × 37
实际母线电压 = (ADC电压 - VBUS_OFFSET_V) × 37
```

当前已经确认参考偏置实测约为 `1.27 V`，代码中的偏置值已按实测值调整。比例暂时仍按原理图使用 `37`。

## 3. 已观察到的现象

### 3.1 VOFA+ 一组内部一致的数据

曾经观察到以下数据：

| 通道 | 数值 |
|---|---:|
| EMFU | 6.5448 V |
| EMFV | 7.3309 V |
| EMFW | 7.1953 V |
| VBUS | 12.8334 V |
| ADC_U | 1.4469 V |
| ADC_V | 1.4681 V |
| ADC_W | 1.4645 V |
| ADC_VBUS | 1.6168 V |

其中：

```text
(1.4469 - 1.27) × 37 ≈ 6.54 V
(1.4681 - 1.27) × 37 ≈ 7.33 V
(1.4645 - 1.27) × 37 ≈ 7.20 V
(1.6168 - 1.27) × 37 ≈ 12.83 V
```

说明软件内部的偏置、比例和 VOFA+ 通道映射是一致的。

### 3.2 PF9 万用表读数与 ADC 换算不一致

另一次测量中：

```text
万用表测 PF9：约 1.55 V
软件 ADC_VBUS：约 1.75 V
```

如果 ADC 参考电压按 3.3 V 计算，而控制板实际 VDDA 约为 3.0 V，则同一个 ADC 原始值会被软件放大：

```text
1.55 × 3.3 / 3.0 ≈ 1.705 V
```

如果实际 VDDA 约为 2.92 V，则：

```text
1.55 × 3.3 / 2.92 ≈ 1.75 V
```

因此当前更优先怀疑 `ADC_VREF` 与 MCU 实际 `VDDA` 不一致，而不是立即修改 VBUS 的分压比例。

## 4. 当前问题判断

### 已确认

- PF6~PF8 是三相 BEMF / 相电压 ADC 输入。
- PF9 是 VBUS ADC 输入。
- BEMF 和 VBUS 的代码换算链路可以按原理图成立。
- `1V24_IN` 实测约为 `1.27 V`，代码偏置已相应调整。
- ADC1 三相电流通道已经配置，但还没有接入电流计算和输出。

### 未确认

- MCU 实际 `VDDA/VDD` 电压。
- ADC 实时 VDDA 与 MCU `VDDA/VDD` 万用表测量值是否一致。
- PF9 万用表测量时是否与 ADC 同一时刻、同一地、同一工作状态。
- PWM 开关纹波是否影响 PF9 的瞬时采样值。
- 原理图中的 VBUS 分压电阻与实际板上阻值是否一致。

## 5. 排查和验证方案

### 第一步：确认实际 ADC 参考电压

直接测量 MCU 的 `VDDA/VDD` 对地电压，不能只测电脑 USB 或电源模块输出端。

```text
若 VDDA ≈ 3.3 V：继续检查 PF9 网络、Rank 和采样时刻。
若 VDDA ≈ 3.0 V：ADC换算必须使用实际 VDDA。
```

### 第二步：验证 ADC 原始值

增加或保留 PF9 ADC 原始值输出，区分以下两种情况：

```text
万用表 PF9 与 ADC 原始值换算结果一致：硬件网络或参考参数有问题。
万用表 PF9 与 ADC 原始值换算结果不一致：检查 VDDA、ADC 通道、采样时刻和接地。
```

### 第三步：暂时使用实测 VDDA 验证

在确认 VDDA 后，可以暂时把：

```c
#define ADC_VREF 3.0f
```

改成实际测量值进行验证。但这只是验证手段，不是最终方案。

### 第四步：VREFINT 动态换算

正式方案已经接入 ADC1 注入 Rank 4，使用 STM32 内部 VREFINT 计算实时 VDDA：

```text
VDDA = VREFINT_CAL × VREFINT实际值 / VREFINT_ADC原始值
```

这样可以避免控制板 3.3 V 供电波动导致所有 ADC 电压同比例偏差。

VOFA+ 新增诊断通道：

```text
通道 18：实时 VDDA
通道 19：VREFINT 原始 ADC 值
```

该功能已经通过代码级检查，但仍需实测通道 18 与 MCU `VDDA/VDD` 的一致性。

### 第五步：验证 BEMF

- PWM 关闭、电机停止时检查三相基线。
- 外力转动电机，确认三相出现周期变化。
- 低速运行时观察三相波形和相位关系。
- 逐步提高转速，确认 BEMF 幅值随转速增加。
- 高速细节使用示波器或低速 VOFA+ 输出，不使用已经验证会卡死的 16 kHz Scope 直出模式。

## 6. 现阶段不采取的措施

- 不因为一次测量结果就把 VBUS 比例从 `37` 改成 `23`。
- 不在 ADC 参考电压未确认前启用过压保护阈值。
- 不把 BEMF 相电压直接当作三相电流。
- 不在电流零点和采样增益未校准前接入电流环。
- 不将本次未实机验证的参数提交为正式版本。

## 7. 后续实现顺序

```text
确认 VDDA
  -> 校正 ADC 电压换算
  -> 验证 PF9/VBUS
  -> 验证三相 BEMF
  -> ADC1 电流零点校准
  -> 电流值换算并输出 VOFA+
  -> 过流保护
  -> 电流环
```
